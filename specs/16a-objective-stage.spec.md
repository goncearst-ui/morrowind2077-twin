# Spec 16a: цель лидера, ключевые результаты, этап и жизненный цикл

Intent: intent/16-intent-objectives.md
Статус: утверждён 2026-10-27 (общее слово Стана: «Утверждаю все твои решения по подготовке оставшихся модулей и создания новых заявок при необходимости»). Код не менять, пока у plan нет строки «Статус: утверждён».
Трек: только двойник. CK: ноль часов.
Метки: [док NN] — из docs/NN; [предл] — моё предложение (Стан принял общим словом 2026-10-27); [решение Стана] — прямой ответ Стана.
Единица времени: 1 тик = 1 сутки.


## 0. Коротко, человеческим языком
У фракции появляется цель лидера: ВЫЖИВАНИЕ, МОНОПОЛИЯ_УЗЛА, АВТАРКИЯ, ГЕГЕМОНИЯ, ИСХОД или ОСВОБОЖДЕНИЕ. Прогресс считается так: у цели есть до трёх условий (KR) на уже существующих числах («держит объект X», «контроль C выше 60 двадцать суток подряд», «у соперника меньше половины людей»); число выполненных условий — этап (ObjStage) от 0 до 3. Цель не вечна: достигнутая меняется по таблице, провалившаяся сворачивается (вожак убит и преемника нет — ВЫЖИВАНИЕ и удар по морали), протухшая (этап не растёт 200 суток) пересматривается. В этой задаче цель ничего не делает в поведении (это 16b): она только измеряется и меняется.

Выключатель `obj_enabled`, по умолчанию False (требует `leader_enabled` и `evolution_enabled`).

## 1. Что входит
1. Состояние фракции: `objective` (0–5, по умолчанию 0), `obj_stage` (0–3), `obj_ctr` (счётчики длительности по KR), `obj_age` (тиков без роста этапа), `obj_target` (имя объекта или соперника, задаёт сценарий), `obj_rival_start` (стартовые числа соперника, фиксируются при установке цели). Названия [док 16]: 0 ВЫЖИВАНИЕ, 1 МОНОПОЛИЯ_УЗЛА, 2 АВТАРКИЯ, 3 ГЕГЕМОНИЯ, 4 ИСХОД, 5 ОСВОБОЖДЕНИЕ.
2. Активные цели — 1, 3, 4, 5; пассивные — 0, и 2 при доктрине 2 (чей путь и так единственный) [док 16]. Потолок: не более `obj_max_active` (2) активных целей на мир; превышение при установке — ValueError.
3. KR-условия — данные (`obj_kr` в params): виды: owns(объект), hold(метрика, оператор, порог, тиков) — счётчик длительности, rival_below(соперник, доля старта), rival_supply_low(соперник, порог days_supply, тиков) — счётчик, prosperity_at_least(порог). Не более `obj_max_duration_kr` (2) KR с длительностью на фракцию — проверка при установке, иначе ValueError [док 16]. Наборы по целям (стартовые, [док 16, 17; числа предл]):
 - МОНОПОЛИЯ_УЗЛА: KR1 owns(цель); KR2 hold(C > 60, 20 тиков); KR3 rival_below(соперник, 0.5).
 - АВТАРКИЯ: KR1 prosperity_at_least(70); KR2 hold(C ≥ 60, 20 тиков).
 - ГЕГЕМОНИЯ: KR1 hold(C ≥ 70, 20 тиков); KR2 архетип соперника Дрейфующие ИЛИ флаг вассальной труа пары; KR3 Manpower ≥ 0.8 стартового.
 - ИСХОД: KR1 owns(цель-площадка); KR2 days_supply ≥ 20; KR3 нет.
 - ОСВОБОЖДЕНИЕ: KR1 owns(узел); KR2 rival_supply_low(соперник, 15, 20 тиков); KR3 Manpower выше стартового и C не выше стартового.
4. Шаг `objective_step()` в фазе 7 до решений: пересчёт KR, счётчиков, `obj_stage`; запись этапа только при изменении, reason KR_<n>; счётчик пишется при каждом изменении, reason OBJ_CTR; сброс счётчика при просадке условия.
5. Жизненный цикл: (а) достигнута (все KR): цель меняется по таблице `obj_next` {1:3, 3:0, 5:0, 4:0, 2:0, 0:0} [предл], этап 0, счётчики сброшены, reason OBJ_DONE, событие objective_done; (б) провалена: вожак убит и преемника нет (правило 1 из 21b → Дрейфующие): цель 0, мораль −`obj_collapse_morale` (15), reason OBJ_COLLAPSE на тике преемственности; при наличии преемника до 16c — цель 0 и этап 0, reason OBJ_SUCCESSOR; (в) протухла: этап не вырос `obj_stale_ticks` (200 = N×10 при N = 20) тиков → цель 0, reason OBJ_STALE; если за это время депо соперника переехало (`obj_target` потерял прежнее положение), reason OBJ_TARGET_LEFT [док 17].
6. Параметры в twin/params.py: `obj_enabled` False, `obj_max_active` 2, `obj_max_duration_kr` 2, `obj_stale_ticks` 200, `obj_collapse_morale` 15, `obj_next`, `obj_kr` [док 16 / предл].

## 2. Приёмка (чек-лист; менять и ослаблять может только Стан)
Сценарии IN строятся на чистой обстановке (как EV: налёты, решения при голоде, войны выключены), с `leader_enabled`, `evolution_enabled`, `obj_enabled`.
| # | Проверка | Обязано выполняться |
|---|---|---|
| IN1 | Ручная установка | цель задана сценарием на тике 1: строка `A.objective` 0 → 1, reason OBJ_SET; этап 0; других строк цели нет |
| IN2 | Этап по KR | МОНОПОЛИЯ у A; штурм на тике 10 забирает целевой объект: `A.obj_stage` 0 → 1 на тике 10, reason KR_1; пока ничего не менялось, строк этапа нет |
| IN3 | Счётчик длительности | C > 60 с тика 1: счётчик растёт на 1 в тик; этап растёт на тике 20; просадка C на тике 25 сбрасывает счётчик в 0, этап снова падает; строки OBJ_CTR на каждом изменении |
| IN4 | Потолок длительных KR | набор KR с тремя длительными для одной фракции → ValueError при установке |
| IN5 | Достигнута | все KR МОНОПОЛИИ выполнены: на том же тике цель 1 → 3, этап 0, счётчики 0, reason OBJ_DONE, событие objective_done |
| IN6 | Коллапс | вожак A убит, преемника нет: на тике преемственности A становится Дрейфующими, цель 0, мораль −15, reason OBJ_COLLAPSE |
| IN7 | Протухла | недостижимые KR 500 тиков: на тике 200 цель 1 → 0, reason OBJ_STALE; ни одна цель не стоит без роста этапа дольше 200 тиков |
| IN8 | Жертва ушла | депо соперника переезжает на тике 50, этап не рос: на тике 200 причина OBJ_TARGET_LEFT, не OBJ_STALE |
| IN9 | Потолок целей | две активные цели у двух фракций; третья активная — ValueError; пассивная АВТАРКИЯ при доктрине 2 третьей не считается |
| IN10 | Выключено | `obj_enabled` = False: журналы прежних сценариев совпадают с эталоном tests/baseline_pre16a.json; ни одной строки `objective`/`obj_*` |

Обратные проверки (R114+): счётчик не сбрасывается → IN3 красный; этап пишется каждый тик → IN2/IN1 (лишние строки); протухание выключено → IN7; потолок целей снят → IN9; мораль коллапса 0 → IN6; причина TARGET_LEFT не различается → IN8. Каждая даёт красный.

## 3. Решения Стана и что осталось
Решения [Стан, общее слово 2026-10-27; рекомендации docs/16]: словарь из шести; KR на существующих числах; счётчики длительности не более двух на фракцию; потолок двух активных целей; цель принадлежит лидеру; месть в словарь не входит.
Допущения [предл]: таблица `obj_next`; числа KR; срок протухания 200 суток; «цель» устанавливает сценарий (в игре — авторинг); KR-набор АВТАРКИИ (в docs — без контрактов снабжения, в двойнике заменено порогом достатка региона).

## 4. Что движок умеет на самом деле (A/B/C)
Двойник: числа и пороги. Для игры, по docs/16: «в CE2 такого механизма нет и не будет, это целиком наша надстройка»; каждый кирпич — Global'ы, условия, таблицы весов (A). Реализация таблицы через вложенные If/ElseIf; Structs в Starfield Papyrus — фича компилятора, не задокументированная построчно (docs/17). Нужно создать: сам слой намерений; каналы в сцене (S7) — отдельно, CK.

## 5. Какие моды это уже делали
Проверено 2026-10-27 (чтение страниц): Starfield, AISS (Nexus 17392): профили фракций для ролевых LLM-реплик (требует внешний провайдер), целевых повесток фракций по странице нет. Starfield, Eve Combat AI (Nexus 17237): локальная модель командует отрядами в бою, постоянных целей лидера нет. Вне Bethesda по заголовкам, страницы не открыты: Astra Exodus (дневник разработчика про «ИИ-фокусы и повестки»). Ближайший прецедент в Project: enRAGE (повестки лидеров банд: район, месть, деньги, «убить игрока», удержание; детерминированно, без рантайм-LLM; research-enRAGE-dll.md, docs/16 «внешнее подтверждение»). Мода Bethesda с измеримыми целями лидера и жизненным циклом цели не нашёл. Поиск неполон.

## 6. Что не входит
Влияние на поведение (16b); наследование и вендетта (16c); сцена; LLM; субфракции.

## 7. Известные риски
1. Цель, не влияющая на поведение (до 16b), в журнале выглядит декорацией: 16a без 16b не включать по умолчанию.
2. KR с длительностью — тикающее состояние; потолок два на фракцию соблюдается проверкой.
3. Числа KR — [предл]; правка по результатам теста «одна цель, два характера» (16b).

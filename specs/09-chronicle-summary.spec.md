## 0. Коротко, человеческим языком
Двойник считает мир, но читать журнал из тысяч строк невозможно. Хроника превращает его в короткие предложения вида «Тик 33: A взяла «Рудник» у B, погибло 12 человек». Это не игровая фича, а проверка шаблонов будущей сводки: если хроника скучна или непонятна, шаблон переписывается до того, как в Creation Kit потрачен хоть час. Главное правило из docs/09: у каждой строки должен быть след в мире (то, что игрок мог заметить в кадре). Нет следа — нет строки. Заодно считается «крепость» фракции от 0 до 100: число для сводки, не для формул.

Модуль не меняет мир: чистая функция над журналом. Выключателя модели нет; хроника запускается отдельно (`python3 chronicle.py <сценарий>`).

## 1. Что входит
1. `twin/chronicle.py`: `render(world) -> list[dict(tick, type, text, trace)]`, чистая функция над `world.log` и `world.events`.
2. Шесть типов [док 09] и шаблоны (имена фракций, объектов и именных подставляются из данных; число допустимо только рядом с именем):
 - T1 штурм: «Тик {t}: {A} {взяла/не взяла} «{S}» у {D}; погибло {k}.» След: 13 + 12a — накладка владельца и следы боя.
 - T2 людей стало меньше: Manpower упал не менее чем на 20% за последние 10 тиков; «У {F} стало меньше людей: было {a}, стало {b}.» След: 12 — пустые койки, могилы.
 - T3 снабжение упало: days_supply пересёк `hunger_threshold` (10) вниз; «У {F} кончается снабжение: хватит на {d} суток.» След: 01 — ступень снаряжения; 12 — штабель ящиков.
 - T4 сменился владелец: строка `site.<S>.owner`; ««{S}» перешёл от {X} к {Y}.» След: 12a — накладка владельца.
 - T5 сменился уклад: событие archetype_change; «{F} больше не {старый}: теперь {новый}.» След: 12 — набор «сборы» до, новый набор после.
 - T6 поглощены чужие: событие absorb (если есть); «{F} приняла {n} чужих.» След: 12 — чужая одежда в наборе. В двойнике событий absorb сейчас нет; шаблон проверяется на искусственном событии.
 - T7 хозяин планеты (14, если событие hegemon_change есть): «Под {X} теперь большая часть планеты.» или отдельная строка «Планета спорная.» След: 12a — накладки владельцев активов.
3. Кандидаты после G6 (по параметру `chronicle_candidates`, по умолчанию False): склад переехал; вожак погиб, преемник {имя} (использует именных 21b); война объявлена / закончена. Каждый со следом из docs/09; в проверке следа участвуют так же.
4. Таблица следов `TRACE` — словарь тип → строка-след; каждая строка хроники получает след из неё; тип без следа не рендерится (строка не создаётся).
5. «Крепость» `strength(world, faction)`: 100 × (0.3 × доля объектов у фракции + 0.3 × min(1, Manpower ÷ стартовый) + 0.2 × armory ÷ 100 + 0.2 × min(1, days_supply ÷ 30)) [док enRAGE: 0.3/0.3/0.2/0.2; «кошелёк» в двойнике нет, заменён армори — упрощение, предл]. Нигде в формулах мира не используется.
6. Параметры в twin/params.py: `chronicle_people_drop` 0.20, `chronicle_window` 10, `chronicle_candidates` False [предл].
7. Процесс: хроника не показывается тестеру слепого теста G6 [док 09]; фиксируется в протоколе теста.

## 2. Приёмка (чек-лист; менять и ослаблять может только Стан)
| # | Проверка | Обязано выполняться |
|---|---|---|
| HC1 | Шаблоны | для каждого из T1–T7 есть шаблон и след в TRACE; искусственное событие каждого типа даёт строку нужного вида (в том числе T6) |
| HC2 | Правило следа | на всех сценариях (70 прежних, EV, PL, CR и новые) каждая строка хроники имеет непустой след из TRACE; события неизвестного типа строк не создают |
| HC3 | Чистота | render() не меняет мир: длина журнала, события и поля фракций до и после совпадают; два вызова дают одинаковый список |
| HC4 | Имена, не числа | каждая строка содержит имя фракции или объекта; нет строк, состоящих только из чисел |
| HC5 | Содержание | DS1: есть хотя бы одна строка T1 с верными атакующим, защитником, объектом и тиком из события; EV-сценарий со сменой уклада: строка T5 с верными старым и новым укладом и тиком |
| HC6 | Нет шума | один штурм даёт одну строку T1 (не по строке на каждую запись журнала); T4 и T1 об одном и том же захвате не дублируют потери |
| HC7 | Крепость | пустая фракция (нет объектов, людей, армори, запаса) → 0; полная (все объекты, старт людей, armory 100, запас ≥ 30) → 100; каждое слагаемое монотонно; не вне 0..100 |
| HC8 | Без обратной связи | журнал мира при вызове render() после каждого тика равен журналу без вызова (строка в строку) |
| HC9 | Кандидаты | `chronicle_candidates` False: строк кандидатных типов нет; True: есть, со следами |

Обратные проверки (R109+): шаблон без следа → HC2 красный; render() дописывает в журнал → HC3, HC8; шаблон T1 печатает только числа → HC4; T1 дублируется по записям журнала → HC6; слагаемые «крепости» не нормированы → HC7. Каждая даёт красный.

## 3. Решения Стана и что осталось
Решения [Стан, общее слово 2026-10-27; рекомендации docs/09]: шесть типов в MVP, потолок не двигается; хроника — инструмент приёмки; крепость — только для сводки; правило следа блокирующее.
Допущения [предл]: порог T2 20% за 10 тиков; замена «кошелька» армори; T7 как седьмой тип потому что 14 прямо требует строку в сводке; кандидаты выключены.
Оценка читаемости хроники человеком («пересказывает прогон по хронике», docs/09 S0) — ручная проверка Стана на отчёте; в чек-лист не входит.

## 4. Что движок умеет на самом деле (A/B/C)
Двойник: текст над журналом; Creation Kit не затронут. Для игры, по docs/09: сводка вариантом A — реплики по условиям на Global (A); подстановка имён через text replacement из алиасов — сигнатура под Starfield не проверена (B/C); произвольный динамический текст в терминале — неизвестно, спайк; журнал событий кольцевым буфером в Papyrus — вероятный основной вариант. Хроника двойника в игру не уходит.

## 5. Какие моды это уже делали
Проверено 2026-10-27: в поиске по запросам про новости и сводки мира для Starfield не нашёл мода, который печатает хронику событий NPC-фракций; результаты поиска были общими новостями об игре. Docs/09 называет прецеденты: газеты и «хроника мира» enRAGE (RDR2, внешний мод, разобран в research-enRAGE-dll.md) и новостная лента КПК S.T.A.L.K.E.R. (A-Life). Поиск неполон.

## 6. Что не входит
Игровая сводка; подстановка имён в Message; терминал; LLM; чатер; оценка читаемости.

## 7. Известные риски
1. Строка без следа удобна для автора: проверка HC2 блокирующая.
2. Хроника утекает в игру («у нас же красивый текст»): процесс G6 и правило следа.
3. T6 в двойнике пока не порождается: шаблон проверяется на искусственном событии, при появлении событий поглощения сценарий пересматривается.

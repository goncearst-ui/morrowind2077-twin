## 0. Коротко, человеческим языком
Сейчас объект принадлежит одной фракции целиком, а у региона нет понятия «кто в нём хозяин». 13a добавляет число: какую долю объектов региона держит каждая фракция. Число вычисляется из того, кто чем владеет, и ничего не хранит. Оно нужно двум вещам: сводке (09) и, по выключателю, доходу (06): фракция, чей объект стоит среди чужих, получает с него меньше. Инерции из enRAGE (15% разрыва в сутки, память 4%, поражение ÷2) на первом шаге нет: по решению Стана оставить вывод без динамики и вернуться к инерции только если RG-сценарии покажут рывки.

Выключатель `region_share_enabled`, по умолчанию False; без него журналы прежних сценариев не меняются.

## 1. Что входит
1. Доля: share(F, R) = число объектов региона R у фракции F ÷ число всех объектов региона R. Объекты без владельца считаются в знаменателе. Если в регионе нет объектов, долей нет.
2. Публикация (модуль 13, производная): в конце фазы 8 каждого тика пересчитываются доли; в журнал пишется только изменившаяся: `region.<R>.share.<F>`, old, new, reason SHARE. Пересчёт на тике захвата, а не на следующем.
3. Хозяин региона: dominant(R) = фракция с долей строго больше 0.5, иначе нет. Только для сводки (09), в журнал не пишется.
4. Доход по выключателю `share_income_k` (0 = не влияет, по умолчанию 0): доход объекта = yield × (1 − k + k × share(владелец, регион объекта)). При k = 0.3 и доле 1.0 доход прежний; при доле 2/3 доход 0.9 от прежнего [предл].
5. Параметры: `region_share_enabled` False, `share_income_k` 0.0 [предл]. Оба в twin/params.py.

## 2. Приёмка (чек-лист; менять и ослаблять может только Стан)
Сценарии OS строятся как чистые (налёты, контрабанда, решения при голоде и войны выключены, как EV/PL), с регионом «Перевал» из трёх объектов.
| # | Проверка | Обязано выполняться |
|---|---|---|
| OS1 | Вычисление | A держит 2 объекта «Перевала», B один: в журнале тика 1 строки share A = 2/3 и B = 1/3 (с точностью 1e-9) |
| OS1b | Без владельца | один объект без владельца, A держит 2: share A = 2/3 (не 1.0) |
| OS2 | Сумма | на 40 тиков с принудительными штурмами сумма долей владельцев + доля без владельца = 1.0 в каждом тике и каждом регионе |
| OS3 | Тик события | принудительный штурм на тике 10 (B берёт объект у A): строки share A и B меняются ровно на тике 10, не на 11 |
| OS4 | Хозяин | A 2/3 → dominant A; 1/2 на 1/2 → нет хозяина; 3 из 6 у A → нет (строго больше 0.5) |
| OS5 | Доход | k = 0.3, A держит 2 из 3: expected_income(A) = 0.9 × суммы доходов двух объектов; k = 0: ровно сумма |
| OS6 | Без состояния | произвольные владельцы, выставленные прямо в объектах перед шагом, дают те же доли, что вычисление по формуле (нет памяти между тиками) |
| OS7 | Выключено | `region_share_enabled` = False: журналы всех прежних сценариев (EV, PL, CR и 70 прежних) совпадают с эталоном tests/baseline_pre13a.json; ни одной строки `region.*.share.*` |

Обратные проверки (R70+): знаменатель без бесхозных объектов → OS1b красный; пересчёт на следующем тике → OS3; k не используется в доходе → OS5; порог хозяина ≥ 0.5 → OS4; доля хранится и инерционно ползёт к цели → OS6. Каждая даёт красный.

## 4. Что движок умеет на самом деле (A/B/C)
Двойник считает доли над своими данными; Creation Kit не затронут. В docs/13 владение — наш Global `TF_Asset<N>_Owner` (A, наш); долю как число в Starfield CK считает наш скрипт по этим Global'ам (A для арифметики). Что показывать игроку и чем, решает 09/12a; движковой «доли территории» в Starfield нет, это функция, которую нужно создать. Динамика (инерция) в документах не описана — нужно создать, в 13a не входит.

## 6. Что не входит
Инерция, память, поражение ÷2; связь доли с порогом штурма; доля в 12a (накладка владельца); хранение доли.

## 7. Известные риски
1. k = 0.3 — стартовое число; на стенде 08f доход может сместиться незаметно или слишком сильно. Выключатель по умолчанию выключен.
2. Нет инерции: рывки при серии захватов. Критерий возврата — RG-сценарии и стенд 08f.
3. Регион «common» у старых сценариев содержит все объекты: доли там всегда делятся между всеми фракциями, и при k > 0 доход там падает; поэтому k = 0 по умолчанию.

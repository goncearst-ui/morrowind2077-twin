## 0. Коротко, человеческим языком
Выжить в тяжёлом бою — значит измениться. После штурма, в котором ярус потерял треть и больше, часть выживших стойких становится закалёнными ветеранами, а часть пугливых — сломленными. Закалённых мир ценит (сила фракции растёт), сломленных наказывает (падает). У именных то же самое меняет сами трейты: трус, переживший бой, уже не бежит, и это необратимо. Никакой случайности: направление арки определяется трейтом, а сколько человек перейдёт — арифметикой.

Выключатель `arc_enabled`, по умолчанию False (именные: требует `npc_state_enabled`, 01; без него вёдра арки работают только на рядовых).

## 1. Что входит
1. Вёдра арки на фракции: `arc_hard` = {"steady": n1, "ordinary": n2} (закалённые внутри своего трейт-ведра) и `arc_brk` = {"skittish": n3}. Закалённый остаётся в своём трейт-ведре, поэтому Manpower не меняется; арка — отдельная ось [док 18: «не замена, а надбавка»].
2. Инварианты: n1 ≤ steady, n2 ≤ ordinary, n3 ≤ skittish в любой момент; если трейт-ведро уменьшилось ниже арочного, арочный счётчик уменьшается до размера ведра (отбор потерь внутри ведра не различает помеченных [предл]).
3. Тяжёлое событие яруса: после разрешения штурма (обе стороны) для каждого трейт-яруса потери ≥ `arc_severe_loss` (0.30) от его состава до штурма [док 18]. Если тяжёлое: из выживших без метки Steady → `arc_harden_steady` (0.15), Ordinary → `arc_harden_ordinary` (0.05), Skittish → `arc_break_skittish` (0.20) переезжают в арочное ведро; число = floor(доля × выжившие без метки). Строка журнала `<фракция>.arc.hard`/`.brk`, old, new, module 18, reason ARC_PROMOTE.
4. Публикуемые производные: `vet_ratio` = (n1 + n2) ÷ Manpower, `brk_ratio` = n3 ÷ Manpower; пересчёт на каждом переезде и при потерях, строки reason ARC_RATIO только при изменении [док 18, регистр 00].
5. ФакторАрки = 1 + `arc_vet_w` (0.3) × vet_ratio − `arc_brk_w` (0.3) × brk_ratio входит множителем в `power()` (13) [док 13, 18]; при пустых вёдрах равен 1.0 и сила тождественна прежней. `visible_power` (что видит атакующий) не меняется.
6. Именные (при `npc_state_enabled`): если трейт-ярус именного (bucket_of по его traits, 01) попал в тяжёлое событие, ApplyArc: Steady → закалён (убрать Neuroticism_High, добавить Neuroticism_Low и TF_Hardened), Skittish → сломлен (убрать Neuroticism_Low, добавить Neuroticism_High и TF_Broken), Ordinary — без изменений [предл]. Необратимо: ни один keyword не откатывается. Строка журнала `<фракция>.named.<имя>.arc`, reason ARC_APPLY. Именной с TF_Broken в стеке пакетов получает Broken_Drink_Pkg (позиция 2 после Avoid_Package), с TF_Hardened — Hardened_Train_Pkg (2b) [док 18].
7. Метрика насыщения для отчёта (не критерий): доля закалённых и сломленных среди живых после каждого тяжёлого события на серии из 20 штурмов с пополнением.
8. Параметры в twin/params.py: `arc_enabled` False, `arc_severe_loss` 0.30, `arc_harden_steady` 0.15, `arc_harden_ordinary` 0.05, `arc_break_skittish` 0.20, `arc_vet_w` 0.3, `arc_brk_w` 0.3 [док 18; все — стартовые гипотезы, калибруются по двойнику].

## 2. Приёмка (чек-лист; менять и ослаблять может только Стан)
| # | Проверка | Обязано выполняться |
|---|---|---|
| AR1 | Тяжёлое событие | чистая функция: состав до (30, 20, 10), после (20, 15, 5): потери Steady 33%, Ordinary 25%, Skittish 50% → закалённых +3 (floor(0.15·20)), сломленных +1 (floor(0.20·5)), Ordinary без изменений |
| AR2 | Лёгкое событие | до (30, 20, 10), после (28, 18, 8): потери 6.7%, 10%, 20% → ни одного переезда |
| AR3 | Помеченные не считаются | уже закалённых 5 из 20 выживших Steady: переезд floor(0.15·15) = 2 |
| AR4 | Инвариант | закалённых 18, Steady стало 10: после события арка Steady ≤ 10; на сетке составов (перебор всех троек до 30 человек с шагом 5, без случайности) инварианты п. 2 никогда не нарушены |
| AR5 | ФакторАрки | Manpower 100, закалённых 20, сломленных 10: множитель 1.03, power() = прежняя сила × 1.03; пустые вёдра → множитель 1.0 и power() равна прежней побитово |
| AR6 | Штурм | принудительный штурм с тяжёлыми потерями защитника: в журнале ARC_PROMOTE на том же тике, vet_ratio/brk_ratio обновлены, Manpower и сумма всех вёдер сходятся |
| AR7 | Именной | офицер из Steady-яруса в тяжёлом событии: traits меняются (Neuroticism_High убран, Neuroticism_Low и TF_Hardened добавлены), пакет Hardened_Train_Pkg; офицер из Skittish — TF_Broken и Broken_Drink_Pkg |
| AR8 | Необратимость | 200 спокойных тиков после AR7: traits и пакет те же |
| AR9 | Сохранение людей | `test_people_conserved` на всех сценариях с `arc_enabled`: арка не создаёт и не убирает людей |
| AR10 | Выключено | `arc_enabled` = False: журналы прежних сценариев совпадают с эталоном tests/baseline_pre18.json; power() не меняется |

Обратные проверки (R103+): порог тяжёлого 0 (всегда) → AR2 красный; доли Steady и Skittish поменяны → AR1; помеченные считаются снова → AR3; клэмпа нет → AR4; веса 0 → AR5; откат keyword'ов через N тиков → AR8. Каждая даёт красный.

## 3. Решения Стана и что осталось
Решения [Стан, общее слово 2026-10-27; рекомендации docs/18]: арка — отдельная ось вёдер; направление определяется трейтом; необратимость; сначала формула, потом перк (порядок калибровки docs/13).
Допущения [предл]: floor вместо округления; для помеченных отбор внутри ведра не различает (арка уменьшается клэмпом); Ordinary у именных не меняются (docs: Ordinary «могут только закаляться, медленнее» — для одного человека нет доли, вместо броска не меняю); числа доков — гипотезы и калибруются по метрике насыщения.

## 4. Что движок умеет на самом деле (A/B/C)
Двойник: арифметика. Для игры, по docs/18: `AddKeyword`/`RemoveKeyword` подтверждены в нативном Papyrus Starfield (Papyrus Index), живут на ObjectReference, поэтому мутация возможна только у размещённых ссылок — именных; рядовые без ссылки меняются только счётчиками. [C] семантика `Confidence` в AI Data (смена keyword её может не менять); [C] override Combat Style в форме Package; [C] условные entry points перков на `HasKeyword`; маркеры распития и тренировки не подтверждены (Object Window). Двойник про эти пункты ничего не утверждает. Сцена и перки — вне этой задачи.

## 5. Какие моды это уже делали
Проверено 2026-10-27 (чтение страниц): Skyrim SE, Fortunate Foes (Nexus 120871): противники фракций получают более сильные боевые перки по мере роста уровня игрока через SPID; опыта конкретного NPC и закалки от событий нет. Skyrim, NPCs Learn Skills and Spells (SPID, по статье): NPC растут по весам навыков вместе с игроком; хранится ли состояние на NPC, статья не говорит. Мода Bethesda, где выживание в бою меняет характер конкретного NPC необратимо и по трейту, не нашёл; это наш дизайн. Поиск неполон.

## 6. Что не входит
Сцена (пакеты, маркеры, фасадная дозировка); перки и Combat Style; затухание вёдер (добавится только если метрика покажет насыщение); личные триггеры именных (гибель друга, предательство); каналы 09.

## 7. Известные риски
1. Числа 0.15 / 0.20 / 0.05 — гипотеза: возможно насыщение (все закалены); метрика п. 7 показывает кривую; затухание вводится отдельной заявкой.
2. Поправка «арка как клэмп» может скрыть переезды при больших потерях; AR4 проверяет инварианты.
3. ФакторАрки меняет исходы штурмов только при включённом `arc_enabled`; сдвиг баланса проверяется стендом 08f.
4. Именной меняет traits, а 01 пересчитывает ярлык: ярлык и ведро должны остаться согласованными (инвариант NP2 из 01 запускается после арки).

## 0. Коротко
Встроенная `sum()` Python 3.12+ суммирует дробные числа с компенсацией. C++ при обычном сложении даст другой последний бит. Решение Стана: в двойнике суммировать простым циклом слева направо. Замер до правок: с простой суммой все 3800 тестов зелёные, включая эталоны и золотые файлы.

## 1. Что входит
1. twin/arith.py: `fsum(iterable, start=0)`: `t = start; for x in iterable: t = t + x; return t`. Порядок слева направо, без компенсации. Ради обратной проверки принимает `_bug=False` (при True вызывает встроенную `sum`).
2. В модулях, считающих состояние мира (twin/model.py, twin/planets.py и все прочие twin/*.py, кроме проверочных x*.py, scenarios.py, extra.py и стендов integration.py, bench.py, chronicle.py), все вызовы `sum(` заменены на `fsum(`. Целочисленные суммы тоже заменяются: результат тот же, правило проще (в модельных модулях встроенной суммы нет совсем).
3. Правила не меняются; новых флагов поведения нет; два флага обратных проверок в twin/params.py (sm_bug_builtin_sum, sm_bug_leftover).

## 2. Приёмка (менять и ослаблять может только Стан)
| # | Проверка | Обязано выполняться |
|---|---|---|
| SM1 | Нет встроенной суммы | в модельных модулях (список выше) нет вызова встроенной `sum` (разбор исходников) |
| SM2 | Простая сумма | `fsum([0.1]*10) == 0.9999999999999999` (встроенная даёт 1.0); `fsum([1, 2, 3]) == 6` и тип целое |
| SM3 | Прежнее не сломано | все прежние тесты зелёные, эталоны baseline_* и золотые файлы tests/golden/ без изменений (MANIFEST.json тот же) |
Обратные: R163 (`fsum` зовёт встроенную сумму) валит SM2; R164 (в разбираемый список добавлен исходник со встроенной `sum`) валит SM1.

## 3. Что движок умеет на самом деле (A/B/C)
Двойник; Creation Kit и SFSE не затрагиваются. Для игры это условие будущей задачи ядра на C++: суммировать так же (reports/23-formula-order.md, пункт 4). Категория C для C++-сборки не проверена (нет сборки).

## 4. Какие моды это уже делали
Проверено 2026-10-28: прецедента побитовой сверки симуляции фракций между Python и C++ в модах Bethesda не нашёл (поиск по страницам модов, Nexus читается плохо; не доказательство отсутствия). Технический факт про `sum()` проверен на самом двойнике (Python 3.13.18).

## 5. Не входит
C++; FMA, округление, форматтер чисел (reports/23-formula-order.md §4); замена суммы в проверочных модулях x*.py и стендах.

Если после замены какой-либо журнал или снимок изменится, это нарушает SM3: тогда остановка и решение Стана (в том числе по tests/golden/). Замер до правок говорит, что этого не будет.

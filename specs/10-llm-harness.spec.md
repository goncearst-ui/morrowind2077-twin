## 0. Коротко, человеческим языком
Настоящую языковую модель в двойник не подключаем. Но главное правило модуля 10 — «сказанное совпадает с логом, а модель ничего не меняет» — можно проверить уже сейчас. Строим три вещи. Сборщик фактов: из мира выписывает про фракцию и персонажа то, что можно знать (архетип, оси, цель, трейты). Сверщик: берёт любое утверждение «фракция X сейчас Контролёры» и проверяет по журналу и состоянию. Заглушка-озвучиватель: говорит строго шаблонами из 09. Когда появится реальная модель, её ответы будут проходить через тот же сверщик.

Выключателя нет: модуль ничего не пишет в мир, его вызовы не меняют журнал.

## 1. Что входит
1. `facts(world, faction, npc=None)` → словарь утверждений вида {ключ: значение}: archetype, axes (R, P, C, M), doctrine, objective и этап (если 16 включён), leader traits, status leader/captured, склад известен (из `know`) и т. п. Читает только то, что публично или известно говорящему (правила знания 08c/09; тайное — склад чужой фракции — не попадает, пока `know` не стоит).
2. `render_prompt(facts)` → текст из ключей и значений в фиксированном порядке (детерминированный). Явный запрет додумывать факты — часть шаблона [док 10].
3. `stub_voice(facts)` → утверждения шаблонами 09 (опирается на twin/chronicle.py).
4. `verify(statements, world, log)` → список расхождений: утверждение, ожидание из состояния/журнала на момент тика. Утверждение — пара (ключ, значение) или (событие, тик, цель).
5. Контроль границы: `assert_read_only(world, fn)` — вызывает fn, сравнивает журнал, мир и счётчики до и после; различие — AssertionError.
6. Параметры в twin/params.py: `voice_template_version` (строка), других нет.

## 2. Приёмка (чек-лист; менять и ослаблять может только Стан)
| # | Проверка | Обязано выполняться |
|---|---|---|
| LL1 | Только чтение | вызов facts / render_prompt / stub_voice / verify на мире после 100 тиков не меняет журнал, состояние и события (assert_read_only) |
| LL2 | Детерминизм | два вызова на одном мире дают тот же текст; два прогона мира дают те же тексты |
| LL3 | Факты == состояние | каждое утверждение facts совпадает с полем мира/журнала на тот же тик (проверка по всем фракциям на тиках 1, 50, 100, 200 сценария DS1) |
| LL4 | Сверщик ловит ложь | подложенное утверждение «A — Хищники», когда A — Контролёры, даёт одно расхождение; подложенное верное — ноль |
| LL5 | Тайна | склад чужой фракции не попадает в facts, пока в `know` его нет; после раскрытия (08c) попадает; сверщик ложь про чужой склад ловит |
| LL6 | Два говорящих | два персонажа с разными трейтами в одной ситуации: промпты различны, факты состояния одинаковы |
| LL7 | Заглушка согласована | утверждения stub_voice по всем сценариям из CHRONICLE проходят verify без расхождений |
| LL8 | Запрет записи | попытка «применить» ответ к миру (любой интерфейс записи в voice.py) отсутствует: в модуле нет вызовов `setf`/`rec`/`player_action`; проверка статическая (поиск по исходнику) |
| LL9 | Нет сети | модуль не импортирует сетевых и случайных библиотек (статическая проверка по исходнику) |

Обратные проверки (R136+): facts подкручен (архетип подменён) → LL3 красный; verify всегда пропускает → LL4; facts раскрывает чужой склад → LL5; в voice.py добавлен вызов записи → LL8; импорт случайных чисел → LL9. Каждая даёт красный.

## 3. Решения Стана и что осталось

## 4. Что движок умеет на самом деле (A/B/C)
Двойник: чтение состояния и сверка. Для игры, по docs/10: мост к внешней модели — обход (Papyrus не умеет HTTP нативно); существующие кирпичи: AISS (аналог Mantella для Starfield), Eve AI (локальная модель в бою), sfse_http (SFSE-плагин); Mantella поддерживает только Skyrim и FO4. Совместимость конкретных модов с нашим реестром не проверена. Нужно создать: сборку промпта в игре и фолбэк.

## 5. Какие моды это уже делали

## 6. Что не входит
Реальная модель; мост; TTS; память об игроке; сцена.

## 7. Известные риски
1. Сверка по ключам не ловит ложь в свободном тексте; это граница двойника (задача будущего: разбор утверждений).
2. Утечка тайны через facts — самое опасное место: LL5 обязателен.
3. Если реальная модель добавит новые виды утверждений, сверщик надо расширять; любое расширение — новая заявка.

## Что получится
C++-библиотека, которая читает любой снимок двойника (schema 1) и пишет его обратно байт в байт; числа записываются и читаются точно; округление и деление совпадают с Python; журналы CSV читаются и пишутся обратно байт в байт. Мир она ещё не считает.

## Шаги
1. Ветка cpp-core-25a от main. Эталон: `python3 -m pytest` на main (3852 зелёных) — для сравнения в конце.
2. cpp/CMakeLists.txt: C++20, -ffp-contract=off, без -ffast-math, предупреждения как ошибки; цели tf_core (библиотека), tf_snapcheck (утилита), тесты через ctest. Заголовок GPL-3.0 в каждом файле.
3. cpp/core/num: запись double в hex в формате Python float.hex() (13 цифр, ноль, минус ноль, субнормальные), разбор, round(x, n) по точному двоичному значению (половина к чётному), floor-деление и остаток для int64 со знаком, проверка переполнения.
4. cpp/core/value: универсальное значение (null, bool, int64, double, строка, список, словарь с порядком вставки); писатель в каноническом виде json.dumps(ensure_ascii=False, separators=(",", ":"), sort_keys=True) (ключи объектов по порядку байт UTF-8, экранирование как в Python); читатель той же грамматики.
5. cpp/core/snapshot: чтение файла снимка построчно (шапка и строки «поле, значение»), запись обратно; в 25a без типизации мира (универсальное значение).
6. cpp/core/csvlog: ячейки с типами (n:, b:, i:, f:, s:), разбор и запись CSV как у csv.writer (минимальное квотирование, перевод строки \n).
7. cpp/tools/tf_snapcheck: для каждого файла прочитать, записать, сравнить байты; для снимков дополнительно проверить, что каждое дробное число записано точной hex-записью.
8. cpp/tools/gen_vectors.py и cpp/tests/vectors/: генерация числовых векторов из Python (сид фиксирован, в файле шапка с версией Python); сами векторы коммитятся.
9. cpp/tests: test_num (V0), test_value, test_snapshot_golden (V1: четыре снимка), test_csv_golden (V1: два журнала). Все читают файлы из tests/golden/ и cpp/tests/vectors/ без изменения.
10. Обратные проверки R176–R180 (определения TF_BUG_*, каждое должно покраснеть минимум в одном тесте): R176 hex сокращён, как %a; R177 округление через floor(x*10^n+0.5)/10^n; R178 ключи объектов не сортируются; R179 порядок словаря при чтении теряется; R180 CSV пишется без квотирования.
11. Сборка и прогон на g++ и на clang++; результат ctest в отчёт. Запуск на MacBook (ARM64) по желанию Стана одной командой: `cmake -S cpp -B build && cmake --build build && ctest --test-dir build`.
12. `python3 -m pytest` (3852 зелёных, без изменений), отчёт reports/25a-report.md (что сделано, на каких компиляторах, что не проверено), коммит, push, PR, копии spec, plan, отчёта и intent в Project.

## Риски исполнения
- Точная запись и округление чисел на другом компиляторе (MSVC) могут отличаться: проверяется только на HP OMEN, в 25a не входит; в отчёт запишу как C.
- Читатель JSON обязан не терять числа больше 2^53: целые читаются как int64, а не как double.
- Генератор векторов опирается на версию Python (3.13); шапка файла фиксирует её.

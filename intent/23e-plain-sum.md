# Intent 23e: простая сумма вместо встроенной (для сверки с C++)

Автор: агент по словам Стана 2026-10-28 09:54 («второе», ответ на вопрос 5: заменить сумму в двойнике простым циклом и заново снять золотые файлы). Статус: выполнено 2026-10-28 (specs/23e-plain-sum.spec.md, plans/23e-plain-sum.plan.md, reports/23e-report.md).
Источник: reports/23-formula-order.md (пункт 4), reports/23d-report.md (находка 1).

## Что и зачем
Встроенная `sum()` Python 3.12+ суммирует дробные числа с компенсацией; C++ при простом сложении даст другой последний бит, а повторять алгоритм CPython неудобно и он зависит от версии Python. Решение Стана: в двойнике суммировать простым циклом слева направо.

## Что измерено (без правок кода, 2026-10-28)
Подмена `sum` простым циклом во всей программе (встроенная функция заменена на время прогона): все 3800 тестов зелёные, включая сверку с эталонами baseline_* и с золотыми файлами tests/golden/. То есть замена, судя по измерению, не меняет ни один журнал и ни один снимок; числа и журналы после неё те же; в снимках изменилась только строка параметров (два новых переключателя обратных проверок), файлы пересозданы с разрешения Стана.

## Что нужно создать
В twin/ функция `fsum(iterable, start=0)` (простой цикл слева направо) и замена вызовов `sum(` по дробным значениям в twin/*.py на неё; целочисленные суммы можно не трогать. Проверка (по образцу SN): тест, который падает, если в twin/ остался встроенный `sum` по дробным; обратная проверка; перегенерация золотых файлов (ожидается идентичность, MANIFEST тот же); обновление reports/23-formula-order.md (пункт 4). Правка tests/test_acceptance.py (только Edit) и tests/golden/ (если файлы изменятся) требуют разрешения Стана.

## Не входит
C++; другие места расхождения (FMA, округление, форматтер): reports/23-formula-order.md §4.

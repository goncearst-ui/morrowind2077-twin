# Двойник Morrowind 2077 — правила работы для агента

Владелец и единственный утверждающий: Стан. Он не разработчик — объяснять в терминах поставки, без жаргона.

## Конвейер (каждая задача)
1. intent/ — заявка. Пишет Стан, агент помогает.
2. specs/ — спецификация. Обязательны разделы «Что движок умеет на самом деле (A/B/C)» и «Какие моды это уже делали».
3. plans/ — план. Код не меняется, пока у плана нет строки «Статус: утверждён».
4. tests/ — чек-лист приёмки. Агент не ослабляет его, чтобы пройти. Менять — только Стан.
5. Набор «штопор» (DS1, DS2, DS4) — регрессионный гейт для любой следующей задачи.
6. «Готово» — только с зелёным `python3 -m pytest` или с отчётом, где каждая красная строка объяснена.

## Правила модели
- Без случайности. Без людей поштучно — только вёдра (03). Без притока людей «из ниоткуда» (§1).
- Событие «раз в сутки с шансом p%» из чужих источников (enRAGE и др.) заменяется накопителем: каждый тик к счётчику прибавляется p, при ≥100 событие и счётчик −100. Средняя частота сохраняется, бросков нет (принято Станом 2026-10-26).
- Все числа — в twin/params.py с меткой [док NN] или [предл].
- Каждое изменение состояния — строка журнала: tick, phase, module, target, old, new, reason_code.
- Двойник не утверждает ничего о Creation Kit. Метки A/B/C живут в документах модулей.

## Направление масштаба (решение Стана 2026-10-28, в двойнике ещё НЕ реализовано)
Действующие правила выше остаются в силе до утверждения плана задачи 23 (intent/23-scale-cpp-core.md). Что решено на будущее: именных станет сотни вместо 5–10 (рядовые остаются в вёдрах); журнал станет двухуровневым (подробный для именных и спорных событий, сводный для остального); «тихие» планеты считаются реже и сводно; ядро будет переписано на C++ и сверяться с двойником побитово на уменьшенных мирах (4 фракции, до 20 планет, до 100 именных, 1000 тиков). Агент не применяет эти решения к коду двойника, пока у плана задачи 23 нет строки «Статус: утверждён». Обновление 2026-10-28: план 23 утверждён и выполнен в двойнике (23a–23d); всё новое включается флагами и параметрами (log_two_level_enabled, named_max, multi_planet_enabled), по умолчанию выключено, поэтому правила выше по умолчанию действуют как прежде. Переписать правила гранулярности и журнала под принятое решает Стан.

# Двойник Morrowind 2077 — правила работы для агента

Владелец и единственный утверждающий: Стан. Он не разработчик — объяснять в терминах поставки, без жаргона.

## Конвейер (каждая задача)
1. intent/ — заявка. Пишет Стан, агент помогает.
2. specs/ — спецификация. Обязательны разделы «Что движок умеет на самом деле (A/B/C)» и «Какие моды это уже делали».
3. plans/ — план. Код не меняется, пока у плана нет строки «Статус: утверждён».
4. tests/ — чек-лист приёмки. Агент не ослабляет его, чтобы пройти. Менять — только Стан.
5. Набор «штопор» (DS1, DS2, DS4) — регрессионный гейт для любой следующей задачи.
6. «Готово» — только с зелёным `python3 -m pytest` или с отчётом, где каждая красная строка объяснена.

## Правила модели
Режимов два. Базовый: флаги масштаба выключены (так в коде по умолчанию); это регрессионный эталон, его журналы и золото не меняются. Масштабный: включены log_two_level_enabled, multi_planet_enabled, named_max больше 10 и, для слоя сцены, scene_enabled; новые задачи рассчитаны на него. Смена значений флагов по умолчанию — отдельное решение Стана, агент её не делает.

Общее для обоих режимов:
- Без случайности. Без притока людей «из ниоткуда» (§1).
- Событие «раз в сутки с шансом p%» из чужих источников (enRAGE и др.) заменяется накопителем: каждый тик к счётчику прибавляется p, при ≥100 событие и счётчик −100. Средняя частота сохраняется, бросков нет (принято Станом 2026-10-26).
- Все числа — в twin/params.py с меткой [док NN] или [предл].
- Арифметика пишется так, чтобы C++ мог повторить её до бита: суммы только через twin/arith.fsum (встроенная sum запрещена в модельных модулях, проверка SM1), выражения не упрощать и не переставлять; места риска перечислены в reports/23-formula-order.md.
- Новое обычное поле Params или World меняет золото tests/golden/; пересоздавать золото можно только с разрешением Стана. Поля с «_bug_» в имени (переключатели обратных проверок) золото не меняют.
- Двойник не утверждает ничего о Creation Kit и о плагине: всё, что касается игры, остаётся категорией C, пока не проверено. Метки A/B/C живут в документах модулей.

Люди:
- Базовый режим: без людей поштучно, только вёдра (03); именных 5–10 на фракцию (named_max = 10).
- Масштабный режим: именные поштучно, до сотен (named_max и список twin/data/named_roster.json); рядовые только вёдра, поштучно их не заводить. Переход рядового в именные в двойнике не реализован; для него нужна отдельная заявка.

Журнал:
- Базовый режим: каждое изменение состояния — строка журнала (tick, phase, module, target, old, new, reason_code) в одном плоском списке.
- Масштабный режим: два уровня. Подробный: строки с теми же семью полями для именных и для спорных событий (причины с префиксами из disputed_prefixes в twin/params.py: RULE_, KR_, WAR_END_, PLAYER_, VENDETTA, OBJ_, PLANET_, SCENE_). Сводный: всё остальное, итогом по окнам в 10 тиков. Новая причина, которую надо видеть поштучно, получает префикс из этого списка; иначе она уйдёт в сводный уровень.

Тихие планеты (масштабный режим): планета без событий 10 тиков (quiet_window_k) считается пакетом раз в 7 тиков (quiet_period_p), сводно; дома фракций всегда активны; штурм, налёт и присутствие игрока будят планету в тот же тик.

Штурм при игроке (слой сцены 24a): если игрок рядом с объектом, исход решает сцена и игрок; без игрока исход решает тик по соотношению сил (13). Числа сцены стартовые ([предл]), не откалиброваны.

## Направление масштаба (решение Стана 2026-10-28)
Принято и реализовано в двойнике за флагами: именных сотни вместо 5–10 (23b); журнал в два уровня (23a); несколько планет и «тихие» реже и сводно (23c); простая сумма для побитовой сверки (23e); слой сцены (24a, scene_enabled). Правила «Правил модели» выше переписаны под это решение 2026-10-28 по слову Стана; базовый режим с выключенными флагами остаётся эталоном.

Цены принятого, о которых надо помнить при новых задачах:
- Хроника (09) и озвучка (10) читают только подробный уровень журнала; при включённом флаге хроника строится по неполному журналу.
- Сводный уровень теряет разбивку по фракциям.
- Список спорных причин (disputed_*) составлен агентом [предл] и Станом не просмотрен.
- В хаотичном режиме (штурмы, вымирание) мир с тихими планетами и пошаговый мир расходятся в исходах: суммарные начисления верны, траектории нет. В двойнике выигрыш тихих — размер журнала, не время.

Ещё не сделано и без утверждённого плана не начинается: ядро на C++ (сверка побитово с двойником на уменьшенных мирах: 4 фракции, до 20 планет, до 100 именных, 1000 тиков), межпланетный уровень (заявка 24b), всё, что касается плагина и Creation Kit (спайки на HP OMEN только после фасада 12/12a и версии 1 в CK).

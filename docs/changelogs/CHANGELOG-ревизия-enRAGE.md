# CHANGELOG — ревизия «enRAGE» (2026-10-19)

*Источник ревизии: разбор RDR2-мода **enRAGE — Living World and Nemesis System** (nicklovin99, Nexus Mods, RDR2 mod 10967, v0.9.5 от 19.10.2026, ранний доступ). Внешний C#-скрипт на ScriptHookRDR2 + ScriptHookRDR2DotNet V2, состояние мира во внешних JSON по сохранениям, автор указал использование Claude Code.*

*Принцип ревизии: из enRAGE берутся **правила и ошибки калибровки**, а не код и не архитектура. Движок другой; всё, что ниже названо механикой, у нас **строится заново** на примитивах, уже принятых в проекте. Ни одна строка не утверждает, что Creation Kit или Papyrus умеют то, что умеет enRAGE.*

## Найденные дефекты собственного дизайна

Ревизия не только добавила идеи — разбор ошибок enRAGE вскрыл два дефекта, которые были у нас в документах:

1. **Формула потерь 13** уносила половину *всей* фракции за проигранный штурм — хуже, чем ошибка enRAGE 0.9.4, которую поймали игроки (крупные банды вымирали за несколько суток; один бой — 60+ человек). Исправлено в 13; тест — DS1 и DS4.
2. **Цикл дезертирства 06** (`While HungerDebt >= DesertionCost`) не имел потолка за тик — при накопленном долге фракция теряла десяток человек разом. Исправлено в 06; тест — DS2.

Плюс уточнение контракта: `TF_KnownDeposit_<N>` числился за двумя писателями (09 и 13) — закреплён за 09.

## Что сознательно не взято

| Идея enRAGE | Почему нет |
|---|---|
| **Гарантированный ежедневный приток местных рекрутов** у разбитой банды | процедурный бэкфилл, запрещён §1; ловится compliance-проверкой в CI (11) |
| Внешнее ядро (C# / JSON вне сейва) | горячий слой обязан быть ванильным (11, правило 1); SFSE-плагин допустим только для холодного слоя, спайк |
| Хранимый разум у каждого встреченного NPC (потребности, стресс, цели) | нарушает «личное выводится, а не хранится» (01) и O(фракций) (00) |
| Имя и биография любому ванильному NPC при приветствии | противоречит аддитивности (01); механизм рантайм-присвоения под Starfield не проверялся |
| Плашки над головой с именем и отношением | UI-модификация, не проверена под Starfield (C) |
| Полный ростер и страница каждого человека в меню | нарушает правило следа (09): мир превращается в таблицу |
| Фоновые стычки между фракциями | главный источник их ошибки калибровки; у нас каждое столкновение — решение дерева |
| 7 темпераментов дословно | у нас 6: «Жадный» и «Гордый» требуют keyword'ов без потребителя |
| Месть как цель лидера | у нас временный модификатор (16): не меряется KR |
| Бренд «Nemesis» | Nemesis System — запатентованная технология WB (US 10,926,179); позиционирование мода остаётся «фракционная симуляция с последствиями», личная вражда — один из выходов системы. Не юридическая оценка |

## Затронуто, но не правилось в этой ревизии

Документы, где ревизия создаёт мелкие несоответствия; править при следующем касании модуля:

- **03 Ростер:** новые `reason_code` из 19 (`RELEASED_DESERTED`, `CAPTURED`) и использование ведра `Captured`; инвариант «ярлык темперамента согласован с ведром» (01 S2b).
- **12 Фасад:** склад как адресный след (штабель ящиков уже в списке, добавить «на какой площадке»); засада 19 как ещё одна накладка категории B.
- **12a Вертикальный срез:** расстановка склада на площадках-кандидатах.
- **07 Архетипы:** нет прямых изменений; проверить, что вендетта (16) не создаёт затенения в обходе.
- **GLOSSARY:** новые термины — склад, удар по складу, опознание, темперамент, вендетта, снимок, набор «штопор», хроника двойника, настройка (класс Global'а).

# Отчёт 25a: C++-ядро, ступень 1 — каркас, числа, снимок

Статус: сделано. C++: 6 из 6 тестов зелёные на g++ 13.3 и на clang++ 18.1 (x86-64), обратные проверки R176–R181 краснят тесты на обоих. Python: 3855 зелёных (254 с), без изменений. Это арифметика и файлы; игру, Creation Kit и SFSE ступень не затрагивает.

## Что сделано
- Новая папка cpp/ (по ответу Стана на вопрос 1 spec §9): библиотека tf_core (около 1100 строк), утилита tf_snapcheck, 6 тестовых программ (ctest), генератор векторов на Python. C++20, внешних библиотек нет, заголовок GPL-3.0-or-later в каждом файле. Сборка: `cmake -S cpp -B build && cmake --build build && ctest --test-dir build`.
- core/num: запись double как Python `float.hex()` (13 цифр, минус ноль, субнормальные), разбор, `round(x, n)` по точному двоичному значению (половина к чётному), целое деление и остаток вниз как в Python, сложение, вычитание, умножение int64 с проверкой переполнения.
- core/json, core/value: JSON-подмножество (целые int64, строки, массивы, объекты) и дерево значений как в twin/snapshot.py: целое и дробное различаются, словарь хранит порядок вставки, множество пишется отсортированным, кортеж, запись с полями по порядку. Писатель канонический: ключи объектов по байтам UTF-8, без пробелов, русские буквы без экранирования.
- core/snapshot: чтение и запись файла снимка (schema 1), проверка «каждое дробное число записано точной hex-записью» (перенос exact_report).
- core/csvlog: CSV как у csv.writer (минимальное квотирование, "\n"), ячейки n:, b:, i:, f:, s:.
- tools/gen_vectors.py и cpp/tests/vectors/ (7 файлов, 62 тыс. строк, 3,3 МБ): числовые векторы считает Python 3.13.18, сид 20261028; повторный запуск даёт те же файлы.
- tools/reverse_checks.py: сборка с одним внесённым дефектом на каждом компиляторе.

## Отличия от плана
- Тестовых программ шесть, не четыре: добавлены test_json и test_csv (векторы для JSON и CSV), потому что золотые файлы не содержат ни кавычек, ни запятых, ни спецсимволов в строках.
- Добавлена обратная проверка R181 (целое деление), она в плане не значилась.
- Объект JSON хранится двумя параллельными списками (ключи и значения): пара «строка, Json» внутри Json не собралась на clang++.
- Читатель строже Python: повтор ключа в объекте, дробное число в JSON, целое вне int64 и недопустимый UTF-8 дают ошибку. В золотых файлах ничего такого нет.

## Что не проверено (категория C)
- MSVC на HP OMEN: флаги `/fp:precise /fp:contract-` записаны в CMakeLists как предположение, сборка не запускалась. Работают ли там `std::to_chars` и `std::from_chars` для double с точным округлением «ничьих», покажут те же векторы V0 при первой сборке.
- ARM64 (MacBook): не запускалось. Команда одна: `cmake -S cpp -B build && cmake --build build && ctest --test-dir build`.
- Запрет слияния умножения со сложением (-ffp-contract=off) в 25a ничем не проверяется: в числах этой ступени нет выражений «умножить и сложить». Проверка начнётся с 25c, когда появится арифметика мира.
- libc++ (стандартная библиотека clang на macOS): в версиях до LLVM 20 нет `from_chars` для double. Если сборка на MacBook упрётся в это, заменю на `strtod` с проверкой векторами.
- Векторы привязаны к Python 3.13: округление и csv в другой версии Python могут вести себя иначе; версия записана в шапке каждого файла.

# Отчёт 16a: цель лидера, ключевые результаты, этап, жизненный цикл

Статус: сделано. Тесты: 2658 зелёных (pytest, 56 с). Эталон tests/baseline_pre16a.json снят до правок кода; при obj_enabled = False журналы всех сценариев совпадают с ним.

## Что сделано
- Флаг obj_enabled (по умолчанию False; требует leader_enabled и evolution_enabled).
- twin/objective.py: виды KR (owns, hold, rival_below, rival_supply_low, prosperity_at_least, rival_arch, manpower_ratio_at_least, supply_at_least, mp_up_c_not_up) как чистые функции; наборы по целям лежат в params.obj_kr.
- model.py: поля цели на фракции, set_objective (установка сценарием), objective_step, сброс цели при коллапсе и смене вожака, события objective_done / objective_stale.
- IN1–IN10 (twin/x16a.py); обратные R114–R119, каждая валит свою проверку.

## Отклонения и допущения (прошу взглянуть)
- Шаг objective_step стоит в конце тика (фаза 8), а не в фазе 7 до решений, как в spec п. 4. Причина: IN2 требует, чтобы этап вырос на тике штурма, а штурмы фазы 7 идут после шага «до решений». Критерий IN2 не ослаблен; цена: решения следующего тика (16b) видят этап, посчитанный в конце предыдущего. Если нужен именно порядок из spec, IN2 придётся перенести на тик 11 — решение Стана.
- Возраст цели считается включая тик установки: цель, заданная на тике 1, протухает на тике 200 (IN7).
- Счётчик длительности не обрезается порогом: растёт, пока условие держится; на IN3 он дошёл до 24 и сбросился в 0 на тике 25 (в spec «сбрасывает в 0», число не названо).
- Причина строки этапа KR_<n>: n — номер первого KR, у которого изменился статус. Для этого на фракции хранится производный кэш obj_met (не игровое состояние).
- Удар по морали при коллапсе и сброс цели срабатывают, только если у фракции была цель не ВЫЖИВАНИЕ.
- KR2 ГЕГЕМОНИИ «или вассальная труа пары»: до модуля 17 пары задаёт параметр obj_vassal_pairs (по умолчанию пусто).
- Подвязка C фракции A в сценариях (ev_pins) и ручная смена численности соперника в IN5 — входы сценария; C иначе сам уходит к покойному значению.
- Правка tests/test_acceptance.py: одна команда sed по ошибке прошла мимо Edit, сразу откатил и сделал ту же правку через Edit; итоговое содержимое то же.

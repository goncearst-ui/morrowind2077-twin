# Отчёт 18: личная арка

Дата: 2026-10-27. Plan: plans/18-personal-arc.plan.md. Spec: specs/18-personal-arc.spec.md.
Результат: `python3 -m pytest` — 2400 passed, красных нет.

## Что сделано
- twin/arc.py: чистые функции (переезд в вёдра арки по тяжёлому событию, клэмп, ФакторАрки). В модели: вёдра на фракции, обработка после каждого штурма (обе стороны), публикация vet_ratio/brk_ratio, ФакторАрки в power() (множитель применяется только если он не равен 1.0, поэтому пустые вёдра дают побитово прежнюю силу), ApplyArc для именных при npc_state_enabled (необратимо), пакеты Hardened_Train_Pkg и Broken_Drink_Pkg.
- arc_enabled по умолчанию False; журналы 189 сценариев совпадают с tests/baseline_pre18.json.
- AR1–AR10 (AR7b — вариант для Skittish) зелёные; R103–R108 каждая валит свой сценарий.

## Допущения и замеры
- Тяжёлое событие считается только после штурма (по spec), налёты на объект арку не меняют.
- AR4: сетка 343 состава до штурма × варианты после × варианты арки (более 1000 комбинаций без случайности), нарушений нет.
- Метрика насыщения (не критерий): в AR9 после 20 штурмов с пополнением закалённых и сломленных у обеих сторон 0.0: защитники теряются целиком раньше накопления. Числа 0.15 / 0.20 / 0.05 остаются гипотезой docs/18, калибровка — по стенду.

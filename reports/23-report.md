# Отчёт по задаче 23 (масштаб в двойнике): сводка 23a–23d

Статус: часть «в двойнике» выполнена. Тесты: 3800 зелёных (pytest). C++-ядро, плагин и Creation Kit не входят.

| Часть | Что дало | Отчёт |
|---|---|---|
| 23a | журнал в два уровня (подробный для именных и спорных, сводный окнами по 10 тиков); LG1–LG5, R150–R152 | reports/23a-report.md |
| 23b | именные до 25 на фракцию из фиксированного списка, без продвижения из вёдер; NN1–NN5, R153–R154 | reports/23b-report.md |
| 23c | несколько планет, «тихие» считаются пакетом раз в 7 тиков, хозяин по планете; MP1–MP8, R155–R160 | reports/23c-report.md |
| 23d | снимок состояния с точной записью чисел, эталонный мир 4×20×100×1000, золотые файлы; SN1–SN4, R161–R162 | reports/23d-report.md, reports/23-formula-order.md |

Главные находки: (1) ленивый и пошаговый расчёт совпадают в стабильном мире (людей 0,00%, запаса 1,10%), а в живом хаотичном расходятся по исходам (23c MP6); (2) выигрыш ленивого расчёта в двойнике это размер журнала (8,2% от плоского на ref_small), не время; (3) `sum()` Python 3.12+ компенсированная, для C++ нужна таблица порядка операций; (4) золотые файлы заморожены по набору флагов.

Решения, ждущие Стана: способ суммирования для сверки (повторить `sum()` или заменить циклом в двойнике); заявка 24 (слой сцены, исход сцены решают игрок и сцена); спайки 1–3 на HP OMEN; слияние PR #1.

## Что показали проверки
- Флаг выключен: журналы всех 30 прежних сценариев совпали с эталоном, снятым до правок, строка в строку (закреплено тестом `test_relations_off_matches_baseline`, эталон tests/baseline_pre08a.json).
- Флаг включён: журнал без строк модуля 08 совпадает с журналом при выключенном флаге для всех 30 прежних сценариев. Это закреплено тестом `test_relations_read_only`.
- RL1: все 16 ячеек слоя 1 совпали с таблицей 08.
- RL2: три налёта в один тик дают g_target 4.0 (не 9.0); g на тиках 5–8 = 1 / 2 / 3 / 4; ни один сдвиг не больше 1.0.
- RL3: пять налётов за 20 тиков, g_target не выше 4.0 (потолок реально сработал); после `betray` b = 6.0 и остаётся 6.0 на тике 200.
- RL4a: налёт без захвата, g_target 3.0 → 0 шагами по 0.5 на тиках 10…60.
- RL4b: штурм с захватом, g_target = 3.0 на всех тиках до 100; 10 шагов затухания пропущены паузой; после возврата объекта (тик 101) затухание началось на тике 110.
- RL5: H(пострадавший → обидчик) = база 2.0 + g 4.0 = 6.0; обратное направление равно базе 5.5 и записи пары нет.
- RL6: на тике 200 три пары из шести ниже линии H = 5; пара «Контролёры → Хранители» поднялась до 5.5 (тик 7) и затуханием вернулась ниже 5 (тик 21); есть пары в разных уровнях (например, «Хищники → Хранители» Enemy, обратная Neutral).
- R16 (лимит толчка выключен) валит RL2; R17 (потолок выключен) валит RL3; R18 (пауза выключена) валит RL4b.

## Что подогнано в обстановке сценариев (не в чек-листе)
- В RL-сценариях выключены автономные штурмы (`archetype_assault_threshold` пуст): без этого фракции сами штурмовали на тиках 53, 86, 123 и сбивали счёт обиды. Принудительные штурмы работают как раньше.
- RL3: Хранители 100 человек (а не 60), чтобы доживали до тика 200 после пяти налётов.
- Проверка RL6 (2) требует, чтобы падение ниже линии шло от затухания: в проверке есть шаг затухания между подъёмом и падением.
